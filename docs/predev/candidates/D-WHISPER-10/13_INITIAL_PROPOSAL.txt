Oui. Je cadrerais le produit comme une **application Windows résidente de transcription locale**, pensée pour être disponible en permanence mais quasiment invisible tant qu’on ne l’utilise pas.

Le choix Rust + `whisper.cpp` est cohérent : `whisper-rs` expose les bindings Rust de `whisper.cpp` et peut être compilé avec le backend CUDA ; `whisper.cpp` dispose en plus d’un paramètre `use_gpu` permettant d’activer ou désactiver le GPU à l’exécution. Cela permet donc bien d’envisager **un même moteur avec bascule CPU/GPU**, plutôt que deux applications différentes. ([GitHub][1])

# Plan fonctionnel et technique

## 1. Objectif du produit

Créer une application Windows autonome de transcription audio locale avec deux usages principaux :

1. **Transcription live depuis un microphone**
2. **Transcription d’un fichier audio existant**

L’application fonctionne entièrement en local, sans serveur Python, sans cloud et sans envoi des données audio vers l’extérieur.

Elle démarre avec Windows, reste en arrière-plan dans la **zone de notification Windows** et peut être sollicitée instantanément par :

* clic sur l’icône ;
* menu contextuel de l’icône ;
* raccourci clavier global.

**Hors périmètre initial :**

* capture Teams ;
* capture du son système ;
* intégration Zoom/Meet ;
* bot de réunion ;
* diarisation avancée des participants.

---

# 2. Expérience utilisateur générale

Au démarrage de Windows :

```text
Windows
   ↓
Transcript App
   ↓
pas de fenêtre affichée
   ↓
icône dans la zone de notification
```

L’application reste inactive et consomme très peu de ressources.

Le modèle Whisper **ne doit pas nécessairement être chargé en mémoire dès le démarrage**. Il peut être chargé lors de la première transcription afin d’éviter de monopoliser 2–4 Go de RAM/VRAM en permanence.

### États de l’icône

Prévoir des états visuels simples :

```text
○ Idle
● Listening
◉ Transcribing
✓ Completed
! Error
```

L’état `Listening` doit être immédiatement identifiable pour éviter d’enregistrer involontairement.

# 4. Raccourci clavier global

Prévoir un raccourci configurable, par exemple :

```text
Ctrl + Alt + T
```

Comportement :

```text
Idle
  ↓ raccourci
Start Live

Live
  ↓ raccourci
Stop
```

Donc le même raccourci agit comme un **toggle Start/Stop**.

La crate `global-hotkey` fournit précisément l’enregistrement de raccourcis globaux sous Windows. ([GitHub][3])

Il faudra prévoir dans les paramètres :

```text
Global shortcut
[ Ctrl ] + [ Alt ] + [ T ]

☑ Enable global shortcut
```

avec détection des conflits.

# 5. Mode Live

## Écran principal

Je verrais quelque chose de volontairement très simple :

```text
┌──────────────────────────────────────────────┐
│ Transcript                                   │
│                                              │
│ Microphone                                   │
│ [ Jabra EVOLVE 20 MS                  ▼ ]   │
│                                              │
│ Language        Engine                       │
│ [ French ▼ ]    [ GPU - GTX 1080 Ti ▼ ]    │
│                                              │
│ Model                                        │
│ [ Large V3 Turbo                      ▼ ]    │
│                                              │
│         ● Start live transcription           │
│                                              │
├──────────────────────────────────────────────┤
│ Transcript                                   │
│                                              │
│ 13:42:04 Bonjour, ceci est un test...        │
│ 13:42:09 Nous allons regarder le sujet...    │
│                                              │
└──────────────────────────────────────────────┘
```

Une fois démarré :

```text
● LIVE       00:12:37

[ Stop ]
```

### Fonctionnement live

Pipeline :

```text
Microphone
    ↓
capture audio
    ↓
resampling 16 kHz mono
    ↓
VAD
    ↓
buffers audio
    ↓
Whisper
    ↓
partial transcript
    ↓
confirmed transcript
    ↓
UI + fichiers
```

Le projet `whisper.cpp` contient déjà des exemples de capture microphone et de transcription streaming, ce qui constitue une bonne référence d’implémentation plutôt que de partir de zéro. ([GitHub][4])

# 6. Transcription partielle et définitive

Il faut distinguer deux états.

### Texte provisoire

Pendant que l’utilisateur parle :

```text
… nous allons maintenant regarder les conditions contractuelles
```

Texte visuellement atténué.

### Texte confirmé

Une fois le segment stabilisé :

```text
13:47:18  Nous allons maintenant regarder
          les conditions contractuelles.
```

Le texte confirmé est immédiatement écrit sur disque.

Cela évite de perdre une réunion en cas de crash.

# 8. Gestion CPU / GPU

C’est une fonctionnalité à prévoir dès l’architecture initiale.

Dans les paramètres :

```text
Compute device

● Auto
○ GPU
○ CPU
```

### Auto

Comportement recommandé :

```text
GPU disponible
      ↓
GPU

sinon
      ↓
CPU
```

### GPU

Pour la première version Windows :

```text
NVIDIA CUDA
```

Ta GTX 1080 Ti sera donc utilisée.

### CPU

Force :

```text
use_gpu = false
```

Whisper.cpp expose explicitement ce choix ; son exemple benchmark possède d’ailleurs une option `--no-gpu`, reposant sur ce même paramètre de contexte. ([GitHub][5])

Cela donne une architecture propre :

```rust
enum ComputeDevice {
    Auto,
    Cpu,
    Gpu,
}
```

et non une logique GPU dispersée dans le programme.

# 12. Enregistrement des sessions

Chaque transcription crée une session.

Par exemple :

```text
Transcripts\
└── 2026-10-04 14-32-18\
     ├── audio.wav
     ├── transcript.txt
     ├── transcript.srt
     └── session.json
```

`session.json` conserverait :

```text
date
duration
model
language
microphone
CPU/GPU
Whisper parameters
application version
```

Cela permet de retraiter ultérieurement un fichier dans de meilleures conditions.

# 15. Stack proposée

| Fonction        | Technologie                 |
| --------------- | --------------------------- |
| Langage         | Rust                        |
| UI              | `egui` / `eframe`           |
| Whisper         | `whisper.cpp`               |
| Rust binding    | `whisper-rs`                |
| GPU V1          | CUDA                        |
| Audio capture   | `cpal`                      |
| Resampling      | `rubato`                    |
| Tray            | `tray-icon`                 |
| Global shortcut | `global-hotkey`             |
| Settings        | `serde` + TOML/JSON         |
| Async/tasks     | threads Rust ou Tokio ciblé |
| WAV             | `hound` ou writer maison    |

`whisper-rs` propose actuellement des features de compilation pour CUDA, Vulkan, Metal et d’autres backends, ce qui laisse aussi une porte ouverte à une abstraction GPU plus large ultérieurement. ([GitHub][1])

# 16. Threading

Il ne faut surtout pas faire tourner Whisper sur le thread UI.

Architecture :

```text
MAIN THREAD
UI + Windows event loop
      │
      ├── tray
      ├── hotkeys
      └── UI events
             │
             ▼
       command channel
             │
             ▼
AUDIO THREAD
capture microphone
             │
             ▼
audio channel
             │
             ▼
TRANSCRIPTION WORKER
Whisper CPU/GPU
             │
             ▼
result channel
             │
             ▼
UI
```

Le tray et les global hotkeys nécessitent d’ailleurs un event loop Windows actif, ce qui va dans le sens de cette architecture. ([GitHub][3])

# 17. États internes

Je créerais dès le début une vraie machine à états :

```text
Idle
│
├─→ Initializing
│
├─→ Listening
│
├─→ TranscribingFile
│
├─→ Stopping
│
├─→ Error
│
└─→ Idle
```

Cela évitera beaucoup de bugs du genre :

* double lancement ;
* deux microphones ouverts ;
* modèle déchargé pendant une transcription ;
* raccourci pressé pendant le chargement ;
* fermeture de l’application pendant l’écriture.

# 18. Gestion du chargement du modèle

Je ne chargerais pas Turbo au démarrage de Windows.

Au démarrage :

```text
RAM ≈ application uniquement
VRAM = 0
```

Au premier :

```text
Start transcription
```

on fait :

```text
Load model
↓
Transcribe
```

Puis le modèle reste chargé pendant une période configurable, par exemple tant que l’application reste active.

Option future :

```text
Unload model after
[ 15 minutes ▼ ]
```

Cela permet de libérer la VRAM lorsque l’outil n’est pas utilisé.

## Principe directeur

Le produit devrait donner l’impression suivante :

> **Il est toujours disponible, mais jamais dans le chemin.**

Tu démarres Windows : rien ne s’ouvre.

Tu veux enregistrer :

```text
Ctrl + Alt + T
```

Un petit signal indique :

```text
● Recording
```

Tu repars sur ton travail.

À la fin :

```text
Ctrl + Alt + T
```

et tu obtiens immédiatement :

```text
audio.wav
transcript.txt
transcript.srt
```

Pour moi, c’est ce comportement qui doit guider toute l’architecture. Le **tray, le raccourci global et le chargement à la demande du modèle** sont presque plus importants pour l’expérience utilisateur que la fenêtre principale elle-même.
