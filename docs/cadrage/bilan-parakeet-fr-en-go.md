# Essai GO/NO-GO Parakeet FR/EN, une itération par point

Ce bilan porte sur le GGUF Parakeet TDT 0.6B v3 et NeMo-Speech.cpp v0.2.0 dans le banc isolé `target/parakeet-feasibility/spike02/`. Le code du produit n'a pas été modifié. Les scripts, fixtures et logs sont conservés dans cette racine ignorée par Git. Les comparaisons lexicales prennent **la sortie Parakeet sur le fichier entier** comme référence interne, sans transcription humaine ni mesure de qualité absolue.

| Point et critère | Résultat de l'unique itération | Statut |
| --- | --- | --- |
| **1. Worker hors processus** : 20 inférences consécutives FR/EN sur CPU et GPU, hôte intact, sans `FreeLibrary` du worker | `worker.rs` charge l'ABI une fois par processus, garde un recognizer et traite les chemins reçus sur stdin ; la fin du processus rend la DLL à l'OS, sans appel `FreeLibrary` dans ce worker. Sur la version finale compilée : **20/20 CPU et 20/20 CUDA0**, dix FR et dix EN par calcul, un `WORKER_READY` par processus, 20 appels natifs, codes de sortie 0, hôte vivant (`worker20_summary.json`). L'essai instrumenté antérieur avec `FreeLibrary` reproduit `0xC0000005` côté **CPU** après destruction du recognizer ; un essai CUDA0 instrumenté finit avec code 0 et `drop_api_done`. Ce résultat CUDA unique ne prouve pas que son déchargement sera toujours sûr. | **GO de faisabilité** |
| **2. Horodatages** : offset cumulé de fenêtre, padding de dernière fenêtre, `0 <= start < end <= durée_audio + 0,05 s` pour tous les extraits | Le worker calcule l'offset depuis les échantillons PCM cumulés, sans confondre les trames internes de 80 ms ; chaque entrée est complétée de zéros au multiple de 1 280 échantillons et l'assertion vérifie chaque mot. Sur `fr27.wav` complet, CPU **et** CUDA0 rendent le mot 58 à **26 800–27 120 ms** pour **27 000 ms** d'audio : dépassement de 70 ms au-delà de la tolérance. La campagne s'arrête après deux fichiers terminés par calcul, donc les autres extraits ne sont pas certifiés (`timing_summary.json`, `timing_*.stderr.log`). L'échec déclenche une panique dans le processus enfant ; l'hôte du banc reste vivant. | **NO-GO** |
| **3. Frontières** : variante retenue ≤2 % d'écart à la référence entière, sans mot coupé ou dupliqué | Variante A : seuil RMS 0,001 sur trames de 20 ms, silence ≥200 ms, coupes FR dans des intervalles 15–30 s (3 segments). Écarts FR **11,29 % CPU / 10,75 % CUDA0**, avec désaccord au bord à 59,19 s. EN dure 15,151 s et reste un segment : **0 %**, ce qui n'éprouve aucune frontière anglaise. Variante B : recouvrement 2 s, segments FR de 20 s et EN de 10 s, fusion des mots par leur milieu temporel. Écarts FR **6,99 % CPU / 8,06 % CUDA0**, EN **2,56 %** sur les deux calculs ; un mot est doublé au bord anglais (« life »), ainsi qu'« article » au bord français. WER = distance d'édition des mots normalisés / mots de la sortie entière (`boundary_summary.json`). Aucune variante ne satisfait le critère sur le périmètre FR/EN. | **NO-GO** |
| **4. Langue** : transcription FR/EN sans langue imposée ; identifiant de langue exclu des critères | Les essais antérieurs FR/EN CPU/CUDA0 rendent le texte dans chaque langue avec `language_code=NULL`. `language_count=0` est le comportement attendu de ce couple Parakeet/NeMo, sans incidence sur la réussite de la transcription sans langue imposée. `AC-PARA-16F` a été aligné sur FR/EN et ne demande plus de code de langue détectée. Si l'interface doit afficher ou exploiter ce code, proposer un détecteur de langue séparé dans un futur cadrage ; aucun tel module n'est implémenté ici. | **GO limité FR/EN** |

Les logs `timing_*` proviennent de l'étape intermédiaire où la panique déchargeait encore la DLL lors du déroulement de pile ; le worker final supprime entièrement cet appel. L'assertion temporelle et son échec sur `fr27.wav` sont conservés sans relancer le point 2. Le test de 20 inférences par calcul a été rejoué sur le worker final.

**Statut global : NO-GO.** Les points 2 et 3 échouent aux critères chiffrés ; aucune nouvelle itération ni nouvelle revue n'est lancée dans ce mandat. Les résultats du point 1 ne valent pas intégration du worker dans l'application. Restent expressément hors périmètre : les **23 autres langues** annoncées par le modèle, les autres GPU, le paquet final installable, l'interface et la capture microphone réelle. Le paquet final devra être qualifié distinctement avant toute admission dans le produit.
