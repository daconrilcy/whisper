## Ordre exécutable de la recette release (proposition)

1. **Geler avant admission.** Avec les variables de garde déjà fixées : `cargo build --offline --locked --release -p whisper-worker-parakeet-cpu -p whisper-worker-cpu -p whisper-worker-gpu`. Relever le SHA du `cargo-shared/release/whisper-worker-parakeet-cpu.exe`. Ce worker n'embarque pas la clé attendue de son propre binaire ; il atteste son SHA réel au démarrage. Le script avec `-StageOnly -CandidateId <id>` prépare `%LOCALAPPDATA%\Whisper\.staging\<id>\` : les cinq DLL et deux modèles contrôlés, le worker release figé et les workers Turbo. Le script et la garde refusent une racine de staging hors du `%LOCALAPPDATA%\Whisper` canonique. Le worker Test continue de n'accepter que ses racines Test ; le worker Perso accepte la racine Perso publiée ou son staging, et uniquement `import-single-pass`.
2. **Qualifier sans état produit provisoire.** La feature `personal-qualification` compile un constructeur de clé injectée réservé au harness de `whisper-adapters`, absent du desktop installé. Le harness reçoit les chemins du staging, calcule les SHA du worker/modèle/cinq DLL et compare à la clé candidate imprimée par le worker. Cette clé est passée explicitement à l'admission, l'archive et l'IPC pour la seule recette ; aucun réglage, argument du desktop normal ou variable d'environnement ne peut activer cette admission. Le registre produit contient encore la clé Test uniquement. Après les PASS, inscrire le SHA figé dans la fiche Perso et la branche Perso du registre ; ne pas modifier le worker/DLL/modèles. Un échec n'inscrit aucune fiche et ne publie pas le staging.
