# Note de design — L3 GPU Parakeet pour l'import (DRAFT v3, 18/10/2026)

## Source et frontière

Source produit : [cadrage Parakeet existant](evo-parakeet.md), décisions 03/04/15/16 et correction utilisateur du 17/10/2026 : **L3 est le prochain lot**. Le banc [SPIKE-PARA-02](bilan-parakeet-faisabilite-cloture.md) a obtenu du texte FR/EN sur GTX 1080 Ti CUDA0 et CPU, avec `language_code=NULL`, sans crash hôte. Cette preuve porte sur le banc mono-GPU, pas sur le worker L2 ni sur un paquet installé. Le produit L2 actuel refuse Parakeet si `compute != Cpu` dans `whisper-adapters/src/worker_ipc.rs`, le worker `whisper-worker-parakeet-cpu` crée NeMo avec `gpu=-1`, annonce `backend=CPU` et le registre n'admet que CPU. L3 ne modifie pas Turbo et n'ouvre ni microphone Parakeet, ni import >30 min, ni VAD adaptative/B8.

## Comportement visé

Pour Parakeet/import ≤30 min, **CPU manuel** reste le parcours qualifié L2 ; **GPU manuel** utilise un worker GPU distinct et la clé exacte modèle + worker + DLL CUDA + backend + profil + périphérique. Une panne de GPU manuel est expliquée, sans bascule CPU. **Auto calcul** privilégie ce GPU seulement si une preuve d'identité et la préparation native sont obtenues avant traitement audio ; sinon une seule tentative CPU du **même** modèle est autorisée, avec cause et calcul effectif visibles. Après la première inférence, aucun repli. Le choix Auto et le modèle Parakeet explicitement préféré restent mémorisés. La **langue automatique** Parakeet garde son sens actuel (FR/EN qualifiés, sans identifiant de langue retourné) ; la langue manuelle reste indisponible.

La sélection GPU est conservatrice : qualification produit locale de **la seule GTX 1080 Ti** reconnue sans ambiguïté comme CUDA0. A2 exige ensemble quatre preuves sur le candidat exact : (1) journal `[asr] ... backend=CUDA0` émis par le recognizer NeMo dans le processus worker et capturé avec son PID ; (2) `nvidia-smi --query-gpu=count,name,pci.bus_id,uuid --format=csv`, lancé en processus externe, donnant une seule carte NVIDIA, avec PCI/identité cohérents avec l'inventaire Windows existant ; (3) EN5 GPU en **11,1 s au plus**, soit au plus 50 % de la référence CPU R6 de **22,134 s fixée par décision utilisateur** ; (4) activité GPU pendant cette inférence, échantillonnée par `nvidia-smi` : utilisation ou hausse de VRAM par rapport à l'avant-appel. Chaque preuve est enregistrée avec le SHA du worker et des DLL, le PID et l'intervalle de l'appel. Un élément absent, incohérent ou hors seuil fait échouer A2. Un nom, `Ready`, une allocation isolée ou `CUDA0` seul ne suffisent pas. Plusieurs cartes NVIDIA ou une incohérence avec Windows refusent le GPU avant audio. Aucune promesse multicarte n'est faite par L3.

## Architecture et états

| Frontière | Contrat L3 |
| --- | --- |
| `whisper-core` | Décider CPU/GPU/Auto à partir d'une configuration figée, d'une capacité qualifiée pour **cette clé** et d'une preuve GPU fraîche. Échec GPU manuel sans repli ; Auto au plus une tentative CPU avant inférence. CPU et GPU ont des clés séparées. |
| `whisper-adapters` | Conserver deux chemins de workers Parakeet et deux jeux natifs séparés. Vérifier modèle, worker et DLL avant pending, refuser une clé GPU différente, router la commande, associer le résultat à la génération/tentative/périphérique, préserver les pending d'une ancienne clé sans reprise GPU silencieuse. |
| Worker GPU | Variante Rust hors processus du worker Parakeet, utilisant l'ABI NeMo v0.2.0 et ses DLL CUDA privées avec `gpu=0`. Un seul recognizer par processus : capturer son journal `[asr] ... backend=CUDA0`, vérifier la carte unique via `nvidia-smi` externe et l'identité Windows attendue avant l'ouverture audio, puis lier Result au même processus et à la tentative. Garder DLL chargées pendant la vie du processus et quitter sans `FreeLibrary`. |
| Composition/UI | Montrer GPU seulement si la clé GPU, les DLL et la preuve de périphérique sont disponibles ; afficher le calcul demandé et effectif, la cause d'un repli Auto ou d'un refus manuel. Conserver la matrice Turbo reconnue. |

Le protocole Parakeet IPC v1 conserve ses champs CPU. L'extension prévue ajoute une structure `gpu_evidence: Option<...>` avec `#[serde(default)]` à `Ready` et `Result` : `None` sur CPU, obligatoire sur GPU. Elle contient **seulement** le backend déclaré, `pci.bus_id`, UUID NVIDIA, PID et empreinte du journal `[asr]` capturé. `Command::Transcribe` reçoit `expected_gpu: Option<...>` (PCI/UUID) avec défaut `None` sur CPU ; `Result` possède déjà requête, génération et tentative. Le worker refuse une identité attendue divergente et l'adaptateur compare les valeurs de `Ready` et `Result` à la tentative active. Les patterns exhaustifs CPU des tests IPC sont adaptés mécaniquement sans affaiblir leurs assertions. Si cette extension additive ou l'attribution native n'est pas réalisable dans les chemins prévus, L3a rend `DESIGN_CHANGE_REQUIRED` sans changer de version IPC. Le temps EN5 et les échantillons d'activité sont des **preuves de qualification** dans la fiche du binaire exact ; ils ne sont pas des champs IPC ni une mesure répétée à chaque import.

La frontière de repli Auto est le **premier appel natif de transcription** du worker, après décodage et `Transcribe`. Une erreur pendant l'inventaire, le chargement, le décodage, l'envoi IPC ou la préparation native peut déclencher l'unique tentative CPU Auto si aucun appel natif n'a commencé. Une erreur après cet appel, même avant le premier mot ou `Result`, est terminale pour cette tentative. Un marqueur de phase lié à `(job_id, génération, tentative)` est émis juste avant l'appel et vérifié par l'adaptateur ; l'absence de marqueur lors d'une mort du worker est traitée prudemment comme une phase inconnue et ne déclenche pas un repli. GPU manuel ne se replie jamais.

La variante GPU ne réutilise pas la DLL CPU : le dossier de référence est `target/parakeet-feasibility/spike02/runtime space/cuda/bin/` (NeMo, ggml-cuda, ggml et runtimes CUDA). Les neuf DLL de L3 sont copiées et vérifiées sous la racine d'exécution L3 ; `nvcuda.dll` provient du pilote Windows. Aucun pilote, bibliothèque ou modèle n'est téléchargé. **Aucun appel CUDA par FFI pour LUID/PCI** : le seul `unsafe` autorisé en L3a reste l'ABI NeMo existante dans `native_ffi.rs`, avec `gpu=0`. La mesure de VRAM sous WDDM reste globale et doit être présentée comme telle ; ne pas inventer un seuil de mémoire au registre. Un manque de mémoire constaté produit une erreur explicite (manuel) ou, seulement avant audio, la tentative CPU Auto autorisée.

## Preuve exigée et risques

L3a qualifie le **worker GPU exact**, sans activer le produit : FR87, FR27, EN15, EN5 réel et EN30 synthétique, texte/TXT/SRT quand applicables, durées positives/ordonnées, zéro `InvalidTimestamp`, les quatre preuves A2, dont **EN5 ≤11,1 s**. Faux identifiant, DLL CPU mélangée, DLL CUDA altérée et backend CPU annoncé sont refusés avant audio ; aucune clé CPU n'hérite de cette preuve. Un worker GPU peut traiter plusieurs fichiers puis sortir sans crash hôte. Les autres temps et la VRAM WDDM sont rapportés comme mesures, sans seuil supplémentaire.

L3b route les mêmes recettes par **le parcours applicatif** sur la nouvelle clé GPU ; vérifie GPU manuel, Auto GPU quand prêt, Auto CPU si indisponible avant audio, refus GPU manuel, absence de repli après inférence, pending/reprise liés à la clé, UI et matrice Turbo inchangées. EN30 passe ; >30 min est refusé avant pending. A4 FR/EN et les cinq scénarios R8 sont rejoués sur la clé GPU si leur mécanisme s'applique, avec les adaptations documentées du harness ; aucun test ignoré n'est présenté PASS. La fiche GPU Test est écrite seulement après PASS complet. La recette visuelle Windows reste réservée à l'utilisateur. L6-perso attend ensuite un amendement pour installer le **worker GPU release** et ses dépendances : la fiche Test L3 ne qualifie pas ce futur binaire.

Risque majeur : NeMo/GGML v0.2.0 n'expose pas de getter d'identité physique du recognizer. A2 établit donc une signature **conjointe**, vérifiable mais limitée à cet hôte mono-NVIDIA, à partir du journal de l'instance, de l'identité externe comparée à Windows, de l'accélération EN5 et de l'activité GPU pendant l'appel. Cette signature ne démontre pas une sélection arbitraire sur une machine multicarte ; celle-ci est refusée. Dépendances CUDA privées, disponibilité du pilote et mémoire sont des conditions de qualification, pas des raisons de repli silencieux. Les 23 autres langues et la qualité contre vérité terrain restent hors L3.
