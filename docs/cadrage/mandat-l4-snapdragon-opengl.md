# Mandat proposé pour la recette L4 sur Snapdragon

Le [compte rendu ARM64](recette-windows-arm64.md) identifie les deux essais. Les réservations Qualcomm ont changé entre le diagnostic graphique et l’inférence CPU. Établir l’état initial dans la réservation active. Le desktop fixe eframe 0.35.0 avec Glow dans `crates/whisper-desktop/Cargo.toml` et `crates/whisper-desktop/src/lib.rs`. Le paquet Microsoft peut traduire OpenGL vers DirectX 12. Microsoft a levé la restriction aux applications présélectionnées. Son fonctionnement pour ce candidat x64 émulé reste à mesurer. [Annonce Microsoft](https://devblogs.microsoft.com/directx/windows-graphics-news-2022-q1/) et [fiche Store officielle](https://apps.microsoft.com/detail/9nqpsl29bfff).

## Exécution soumise à accord

1. Sur une réservation autorisant l’installation depuis le Store, l’utilisateur ouvre le bureau interactif du Snapdragon et utilise le compte de la recette. Relever le build Windows, le pilote et la visibilité/version de Microsoft.D3DMappingLayers. Lancer DIAGNOSTIC-OPENGL.ps1 depuis le paquet extrait. Il vérifie l’empreinte du desktop installé. Si la fenêtre est utilisable, passer directement aux essais. Si le candidat manque, utiliser la procédure d’installation existante sur un profil disponible. Un autre échec de démarrage demande un diagnostic distinct.
2. Si la signature Glow se reproduit et que le composant est absent, l’utilisateur installe une fois le produit Store 9NQPSL29BFFF publié par Microsoft dans cette réservation. Le mandat couvre l’accès réseau du Store pour cette installation. Il exclut élévation, changement de pilote, registre, DLL copiée, installation sur le PC personnel et achat. Si le Store est bloqué, demande un compte personnel ou si le composant est déjà présent et l’échec reproduit, consigner et arrêter cette piste.
3. Relever la version installée et relancer une fois le diagnostic dans la même session avec le même exécutable et le même pilote. L’utilisateur confirme une fenêtre affichée **et interactive** (sélecteur CPU/Auto utilisable), ou transmet l’erreur exacte. Conserver le composant dans la réservation pour la recette. Si le contexte reste insuffisant, arrêter avant toute autre installation.
4. Sur une fenêtre utilisable, importer `audio/fr_passage_28-32.wav` avec le modèle Turbo fourni, en CPU puis en Auto, dans deux dossiers de sortie distincts. Relever le moteur effectif et le maintien de la préférence Auto, vérifier TXT/SRT non vides, contenu et horodatages cohérents avec quatre secondes. Comparer au corpus et noter le rendu de « Hong Kong ». Une différence de texte est consignée séparément du succès technique.
5. Si un microphone est exposé dans cette session, enregistrer en CPU puis en Auto. Noter le moteur, le premier bloc confirmé avant arrêt, la phrase finale et les sorties WAV/TXT/SRT de chaque essai. En cas d’absence d’entrée, consigner micro NON EXÉCUTÉ. La session principale ajoute les résultats à la fiche ARM64. Une réussite avec le composant est qualifiée avec cette version et ce prérequis. La CI T42, les mesures d’identité OS/PE prévues par le plan et la décision de distribution conservent leurs critères propres.

## Alternative produit

Si le Store est inaccessible, si l’essai échoue, ou si le produit doit démarrer sur une image Windows vierge hors ligne, étudier un candidat x64 avec rendu wgpu/Direct3D 12. La version épinglée d’eframe expose Renderer::Wgpu et NativeOptions.wgpu_options. Le manifeste actuel active Glow seul et le verrou du projet ne contient pas wgpu. Un mandat distinct devra préciser le périmètre du nouveau rendu, les fonctionnalités et dépendances à résoudre, les éventuels composants du compilateur de shaders, leurs notices, la garde et la reconstruction du paquet. Il devra vérifier le démarrage sur le Snapdragon et la non-régression des deux PC Intel. L’Adreno est un adaptateur graphique potentiel pour la fenêtre ; le choix du worker d’inférence suit la politique CPU/GPU/Auto existante.
