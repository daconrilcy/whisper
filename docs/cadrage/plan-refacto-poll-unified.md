## 5. Invariants et filet d’équivalence

Ordre global inchangé : admission/initialisation exécuteur -> redémarrage éventuel -> pump captures -> événements regroupés (télémétrie, gains, progression) -> previews scheduler -> résultat -> blocage in-flight -> failure hors vol -> fin documentaire -> finals scheduler -> réservation -> préparation -> Ready/repli -> begin/dispatch. Un résultat traité qui retourne None termine l’appel ; **None n’autorise pas à poursuivre une autre phase**. Les extractions utiliseront un contrôle explicite local (`ControlFlow` standard ou équivalent nommé) distinguant poursuivre et retourner None. Aucun état nouveau dans ImportRuntime, aucun transfert temporaire de l’exécuteur hors de son Option qui changerait les chemins de libération/panique.

Conserver les accès disjoints aux champs par fonctions privées ou contexte de références éphémère, <=7 arguments ; aucun trait générique. Ne pas remplacer HashMap, trier les sessions, avancer un timer, déplacer un take/remove, fusionner deux branches d’erreur différentes, changer un texte, le nombre d’appels, la portée d’un verrou ou la durée de vie d’une ressource. Les erreurs volontairement ignorées et le `pump_error` actuellement sans effet restent sans effet. La libération du courant par `collect_poll_event` et celle des pairs en panic/repli restent distinctes. Le drainage avant Stop des chemins voisins reste vérifié par E13/E14 ; ne pas déplacer Stop dans la nouvelle orchestration.

Corpus C, ajouté **avant extraction** et exécuté sur le code de production strictement identique à 08ddfde8 : C01 import nominal ; C02 live preview/final/stop ; C03 GPU Ready échoue puis unique repli CPU, avec pair GPU manuel ; C04 stop pendant préparation avec gate ; C05 stop live avec audio en attente ; C06 EOF et reprise du pair, plus variante panic ; C07 résultat ancien/inconnu (job, génération, appel/tentative, instance) ; C08 reprise d’une session et drainage à séquence non initiale.
